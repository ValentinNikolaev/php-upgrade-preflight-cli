# PHP Upgrade Preflight v0.3.1

Released 2026-08-18.

## Purpose

v0.3.1 is the first patch on the v0.3 line. It keeps schema `0.8`, the PHP `^8.0` runtime floor, every supported Laravel transition, and the whole v0.3 public surface. Two things drive it: evidence integrity in bounded Composer excerpts, and the fact that the packages published for v0.3.0 carried documentation written before publication.

## Fixes

- A shortened Composer output excerpt now ends with `[TRUNCATED: N bytes of output omitted]`, naming the original size. Until now a bounded excerpt simply stopped, so a partial transcript was indistinguishable from a complete one.
- A redaction pass that fails at runtime withholds the value under `[REDACTION_FAILED]` instead of the `[REDACTED]` marker used for a value that was genuinely redacted. Redaction still fails closed; the failure is no longer disguised as an ordinary one.
- The text handed to the redactor is bounded to the excerpt budget plus a margin wide enough to keep a credential that straddles the excerpt boundary whole. Multi-megabyte solver output previously reached the redaction patterns in full, where a PCRE backtrack limit could fail the pass and replace every scenario diagnostic with a single marker.

## Documentation

The v0.3.0 packages were tagged before the public pages were switched to their published state, so the README distributed with them still announced that v0.3.0 was unpublished and told readers to install `^0.2`. This release ships the corrected pages: the v0.3.x line is the supported one, `^0.3` is the install constraint, and the `0.2.x` and `0.1.x` lines are described as archival — available and immutable, but receiving no further releases, security fixes included.

## Upgrade

Existing `^0.3` constraints select this patch automatically:

```bash
composer update php-upgrade-preflight/core php-upgrade-preflight/cli php-upgrade-preflight/laravel --with-all-dependencies
```

New installations are unchanged:

```bash
composer require php-upgrade-preflight/cli:^0.3 php-upgrade-preflight/laravel:^0.3
```

No report-schema migration is required from v0.3.0. Reports identify the tool as `0.3.1` and keep schema `0.8`. A consumer moving from v0.2 still follows the [0.7 to 0.8 migration](../schema.md#migrating-from-07-to-08).

Excerpt text is the only output difference to expect: a truncated excerpt now carries its marker, and a failed redaction pass is distinguishable from a successful one. Any consumer that treated an excerpt as a complete transcript should re-read [Limitations and trust boundaries](../limitations.md#report-projection).

## Release integrity

Publication requires matching verified signed `v0.3.1` tags in the monorepo and all three distribution repositories, checksum-bound archives, dependency inventory and provenance, Linux and Windows consumer audits, Packagist reference verification, and a published-package rerun of the staged quick start with byte-for-byte target immutability.

The four Wiki repositories did not exist when checked on 2026-08-19. This is recorded honestly in the [historical Wiki baseline](v0.3.1-wiki-baseline.json); it is not publication evidence and cannot authorize another v0.3.1 release. Future release candidates must provide `vVERSION-wiki-evidence.json` with a real Wiki commit for every published or unchanged-after-review destination. Wiki repositories are published separately from the three Composer package distribution repositories.
