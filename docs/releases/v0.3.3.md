# PHP Upgrade Preflight v0.3.3

Released 2026-08-21.

## Purpose

v0.3.3 is the third patch on the v0.3 line. It keeps canonical report schema `0.8`, the PHP `^8.0` analyzer runtime floor, every supported Laravel transition, and the existing v0.3 compatibility commitments. No report-schema migration is required.

This release makes the console workflow easier to operate without weakening its automation contract: an explicit interactive wizard can construct an analysis request, long-running analysis reports durable progress on terminal-attached stderr, and the canonical report remains clean on stdout by default.

## Added

- `upgrade-intel wizard`, a line-oriented interactive workflow that detects a Composer project, distinguishes analyzer-runtime PHP from project PHP, collects PHP and package targets, requires an explicit Composer execution policy, reviews the plan, and prints the equivalent shell-copyable `upgrade-intel analyze` command before analysis.
- Explicit package-metadata sources for the wizard: root `composer.json` facts without a Composer process, local-cache-only lookup with network disabled, and configured project repositories that may use network access and inherited credentials. Invalid syntax, found packages, constraints with no discovered matching version, explicit repository not-found results, and operationally unverified results remain distinct.
- Bounded package-version candidates when metadata is available, while retaining a custom Composer-constraint path. A cache miss, timeout, offline or authentication failure, malformed response, or unavailable isolated lookup is never presented as proof that a package does not exist.
- Typed Core analysis-progress events plus CLI and Laravel Artisan renderers. They cover major analyzer phases and Composer scenarios with durable statuses such as `working`, `done`, `blocked`, `invalid`, `timed-out`, `unverified`, and `failed`.
- `--save-report=PATH` for the non-interactive CLI. It preserves the canonical report on stdout and writes the identical rendered bytes to a validated path outside the analyzed project.

## Changed

- Human progress and diagnostics are owned by stderr; report data is owned by stdout unless the existing file-only `--output=PATH` option is selected. Progress appears only when stderr is attached to a terminal, uses no spinner or cursor control, and is suppressed for redirected or captured diagnostics. Reporter failures are observational and cannot alter report status or analysis results.
- The wizard requires terminal-attached stdin and stderr, treats EOF as invalid input (`2`), and returns `130` when the user enters `cancel`, `quit`, or `q` before analysis. Scripts and CI continue to use `upgrade-intel analyze` with explicit options and receive no prompts.
- `--output` and `--save-report` are mutually exclusive. If the additional saved copy fails after stdout is written, the report remains available on stdout, the redacted failure is written to stderr, and the process returns `1`.
- Composer metadata lookup disables plugins, scripts, interaction, and ANSI, applies the configured diagnostic timeout, bounds and redacts diagnostics, and requires an explicit lookup mode. Local-cache-only lookup requests no network and cannot conclude `not_found`; configured-project-repository lookup may conclude `not_found` only from Composer's explicit response for that selected repository universe. Restricted execution remains `unverified` without starting a lookup process until isolated lookup state is available.
- Pull request [#17](https://github.com/ValentinNikolaev/php-upgrade-preflight/pull/17) reorganized the GitHub Pages landing page around a first-run journey, added a recovery-oriented `404.html`, skip navigation and labeled navigation landmarks, improved keyboard focus and color-contrast checks, retained opt-in recordings with reduced-motion behavior, and strengthened the static Pages verifier.

## Upgrade

Existing `^0.3` constraints select this patch automatically:

```bash
composer update php-upgrade-preflight/core php-upgrade-preflight/cli php-upgrade-preflight/laravel --with-all-dependencies
```

New installations keep the same package constraints and PHP requirement:

```bash
composer require php-upgrade-preflight/cli:^0.3 php-upgrade-preflight/laravel:^0.3
```

No report-schema migration is required from v0.3.2, v0.3.1, or v0.3.0. v0.3.3 reports keep schema `0.8`; consumers continue to dispatch on `metadata.schema_version`, not the tool-version string. A consumer moving from v0.2 still follows the [0.7 to 0.8 migration](../schema.md#migrating-from-07-to-08).

The existing non-interactive flags remain supported. Adopt `wizard` for human request construction and keep `analyze` for automation. Adopt `--save-report` only when both stdout and a file copy are wanted; `--output` retains its file-only behavior.

## Security and trust boundary

The wizard does not broaden the analyzer's write boundary: the analyzed project remains immutable input, and any saved report must be outside that project. The package lookup is pre-analysis convenience, not Composer resolution evidence. The actual analysis still runs its bounded scenarios under the separately selected `restricted` or `compatible` Composer mode.

Configured-project-repository lookup can consult global Composer configuration, authentication, proxies, Git/SSH setup, and the network. Its warning and explicit selection are part of the user contract. Redaction limits what diagnostics disclose after execution; it does not prevent Composer or helper processes from reading credentials or contacting repositories.
