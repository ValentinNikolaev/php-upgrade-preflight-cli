# PHP Upgrade Preflight v0.3.2

Released 2026-08-19.

## Purpose

v0.3.2 is the second patch on the v0.3 line. It keeps schema `0.8`, the PHP `^8.0` runtime floor, every supported Laravel transition, and the whole v0.3 public surface. No analyzer behaviour changes. The release exists to publish three things the repository already carried but no tag had yet shipped: the MIT relicensing, the public documentation surface, and a repaired demo script.

## Added

- A public GitHub Pages landing page under `site/`, deployed by its own workflow, with opt-in terminal recordings of the offline demo, an explicit separate-tools-directory install path, and an artifact validator that checks page structure, local references, control contrast, and the licensing and install disclosures before deployment.
- The four-destination release Wiki: canonical pages under `wiki/`, materialized destination copies with per-set manifests and source checksums under `release-wikis/`, and `composer release:wiki:check` wired into `composer check`, so a destination copy that drifts from its canonical source fails the gate.
- Three reproducible VHS recordings of the offline demo beside the existing staged-upgrade recording: the evidence walk from a staged blocker to its Composer command and solver output, the recursive-digest immutability proof, and the Markdown projection.

## Fixed

- `examples/five-minute-demo/run-demo.sh` crashed before reaching its target-immutability check. It still read a stage's `source_impact` entries as embedded findings, while schema `0.8` records them as references into `staged_resolution.source_impact`. The summary now lives in `examples/five-minute-demo/summarize-report.php`, covers stage source-impact references in its drift projection, and fails loudly on an unresolvable reference instead of printing an empty finding. The deterministic test gate executes it against the checked-in canonical report and asserts that it rejects a drifting stage status, a dangling source-impact reference, and a stage that reports no source impact at all.

## Changed

- The release workflow is restructured around an authorization job that validates the release event, normalizes the version once for every later job, and verifies the signed annotated tag and its approved release line through the GitHub API instead of a local ancestry check. The workflow can now also be called by another workflow to verify and package a version without publishing it.
- A Wiki update is mandatory for any change that creates, prepares, or changes a release tag, and the same change must refresh every release-pinned string on the public site.
- The synthetic five-minute-demo fixture packages and demo target manifest declare `MIT` instead of `PolyForm-Noncommercial-1.0.0`, so the demo metadata matches the project's own licence. The demo `composer.lock` and both committed Laravel 10→13 reports are regenerated so their candidate-state fingerprints identify the updated fixture content. The demo's findings, blockers, lifecycles, and guidance are unchanged.
- Both committed demo reports are regenerated from one analyzer run through the shared core report writers, so the committed Markdown is a projection of the same `UpgradeReport` as the canonical JSON instead of a second run whose measured durations disagree.

## Upgrade

Existing `^0.3` constraints select this patch automatically:

```bash
composer update php-upgrade-preflight/core php-upgrade-preflight/cli php-upgrade-preflight/laravel --with-all-dependencies
```

New installations are unchanged:

```bash
composer require php-upgrade-preflight/cli:^0.3 php-upgrade-preflight/laravel:^0.3
```

No report-schema migration is required from v0.3.1 or v0.3.0. Reports identify the tool as `0.3.2` and keep schema `0.8`. A consumer moving from v0.2 still follows the [0.7 to 0.8 migration](../schema.md#migrating-from-07-to-08).

No analyzer output changes in this release. The only reason a consumer sees a different report is the tool version field itself.
