# PHP Upgrade Preflight v0.2.0

Released 2026-08-11.

## Highlights

- Adds schema `0.7`, including explicit platform provenance, a raw `source_inventory`, actionable `source_impact`, and hop-scoped framework guidance.
- Supports Laravel 7→8, 7→9, and every adjacent transition from Laravel 8 through Laravel 13. Same-major requests, downgrades, ambiguous endpoints, and paths whose first required hop is unavailable remain unsupported.
- Adds Composer-metadata adapter discovery, deterministic source ownership, expanded extension-platform modeling, and stronger credential and local-path redaction.
- Keeps the target project immutable by running Composer only in disposable workspaces. The supported external execution path remains a separate Composer tools directory; v0.2.0 does not ship a PHAR or runtime container image.

## Upgrading from v0.1

Reports move from schema `0.6` to `0.7`. Consumers must accept the new required `platform` and `source_inventory` sections, read actionable change estimates from `source_impact`, and treat Composer feasibility independently from `transition.framework_guidance[].status`. Historical schema `0.6` reports and their signed v0.1 fixtures remain unchanged.

Install the release line with:

```bash
composer require php-upgrade-preflight/cli:^0.2 php-upgrade-preflight/laravel:^0.2
```

See the [schema migration guide](../schema.md), [installation guide](../installation.md), and [limitations](../limitations.md) before updating automated consumers.

## Compatibility

The packages support PHP 8.0 through the current PHP 8.x line. The Laravel adapter is installable with Laravel 8 on PHP 8.0, Laravel 9 on PHP 8.0.2, Laravel 10 on PHP 8.1, Laravel 11 and 12 on PHP 8.2, and Laravel 13 on PHP 8.3. An externally installed analyzer may model a newer target PHP independently of the analyzed application's current runtime.

## Release integrity

Release automation requires the exact `0.2.0` tool version, schema `0.7`, `0.2.x-dev` branch aliases and root path versions, `^0.2` internal constraints, matching verified signed `v0.2.0` tags in the monorepo and all three distribution repositories, and clean Linux and Windows consumer audits.

The release archive set contains three package ZIPs, `SHA256SUMS`, a machine-readable dependency inventory, and artifact provenance bound to the source commit and workflow run. Publication is gated on exact checksum and provenance verification, byte-for-byte distribution-tag payload comparison, archive installation, target immutability, synthetic-secret scanning, Packagist synchronization, and a published-package quick start whose analyzed target digest must remain unchanged.
